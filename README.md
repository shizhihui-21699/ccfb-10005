# Sentinel · 支付风控规则控制台

浏览器内运行的支付风控规则引擎控制台：DSL 规则编辑、滑动窗口统计、名单、分组优先级、影子/灰度、历史回放与命中解释、版本发布回滚、以及欺诈团伙关联分析。

所有计算都在浏览器里完成（规则回放与关联分析跑在 Web Worker 中），没有服务端依赖，可以直接 `npm run build` 后托管为静态站点。

## 快速开始

```bash
npm install
npm run dev        # 开发服务器 http://localhost:5173
npm run build      # 生产构建
npm run preview    # 预览构建产物
npm test           # 引擎 / DSL / 生成器单元测试
npm run check      # svelte-check 类型检查
```

打开后：

1. **回放验证** → 「生成并加载」生成 20 万笔带 5 个已知欺诈团伙标签的演示交易 → 「运行回放」。
2. **规则编辑** 左侧按分组浏览规则，右侧编辑 DSL，实时语法诊断、窗口解析、灰度预览。
3. **团伙分析** 无需标签即可从卡/设备/IP 关联中聚类出可疑团伙。
4. **版本历史** 发布快照、对比、回滚。

也可以 **导入 CSV** 用自己的交易数据（`ts, amount_usd, card_hash, device_id, ip, customer_id` 为必需列，其余可选，支持常见别名如 `timestamp` / `user_id` / `card_number`）。

## 规则 DSL

表达式最终必须求值为布尔值。

```text
count(10m, card_hash) >= 5
sum(amount_usd, 10m, card_hash) > 5000
distinct(card_hash, 1h, ip) >= 6
count(1h, ip where amount_usd < 5) >= 10
in_list(card_hash, "blacklist_cards") and amount_usd > 50
card_country == "US" and ip_country in ["NG", "BR"] and amount_usd > 500
```

- **滑动窗口**：`count / sum / avg / min / max / distinct(字段?, 窗口, 分组键...)`，窗口单位 `ms s m h d w`，分组键可多个（`device_id, ip`）。
- **名单**：`in_list(字段, "名单ID")` / `not_in_list(...)`。
- **文本**：`matches / contains / starts_with / ends_with / len / lower / upper`。
- **时间**：`hour_of(ts)`、`weekday_of(ts)`。
- **布尔**：`and` / `or` / `not`，支持 `&& || !` 与括号。
- **过滤**：聚合函数内支持 `where` 子句，例如 `count(1h, ip where amount_usd < 5)`。

编辑器会给出**定位到行列的诊断**：未知字段（带拼写建议）、类型不匹配、窗口位置错误、名单不存在、聚合嵌套等。

### 引擎如何计算窗口

每个聚合（kind + 窗口 + 分组键 + 统计字段 + 过滤条件）在 `WindowStore` 中只维护一份状态，跨规则去重。每个分组键下维护一个时间有序的事件日志和 O(1) 维护的累计和/计数，过期事件在每次写入时按时间前移清理，内存与窗口内事件数成正比。

## 灰度与影子

- 每条规则有 `mode`：`enforce`（生效）/ `shadow`（只记录）/ `off`。
- `rollout` 是 0–100 的灰度比例，按 **卡哈希** 稳定分桶（同一张卡永远落在同一实验臂）。
- 非 100% 的生效规则，落在桶外的交易按影子处理：记录命中但不改变决策。
- 决策按「分组优先级 → 规则优先级」顺序取**第一条生效命中**；`allow` 动作（白名单）会短路后续所有规则。

回放结果里，每条规则都会给出命中数、欺诈命中、误杀、精确率/召回率、涉及金额，以及影子命中数。

## 命中解释

每条命中都会生成条件求值树（`ExplainNode`），标出：

- 哪些条件成立、哪些不成立；
- 在 AND 失败时唯一导致失败的那个条件（`decisive`）；
- 每个聚合叶子的实际值（例如「同卡 近 10 分钟交易笔数 = 7」）。

「命中样本」页可以下钻到单笔交易的完整求值树。

## 回放性能

- 20 万笔 × 18 条规则（含多个滑动窗口）：**约 1.8 秒**，约 11 万笔/秒。
- 列式存储（`Float64Array` / `Uint32Array` 字典编码），每行复用同一个对象，避免 20 万次分配。
- 回放在 Worker 中分块执行并回传进度，主线程始终可交互。

## 欺诈团伙分析

把每笔交易的卡、设备、IP、账户作为图节点，用并查集聚类；对每个簇按「共享基础设施规模、每账户持卡数、设备集中度、交易频次、欺诈占比」打分。

- 公共网络（家庭宽带/NAT）通过 `maxIpFanout` 排除；
- 覆盖全量数据的大簇按 `maxShareOfRows` 当作背景噪声丢弃；
- 结果附带「共享实体」证据表与关联网络图；
- 可以一键把团伙设备/IP 写成观察名单并生成草稿规则。

演示数据内置 5 个团伙（卡测、跑分洗钱、盗刷卡、退款套现、合成身份）+ 单人盗刷，分析可在不读取标签的情况下把它们找出来。

## 目录结构

```
src/lib/dsl/       词法、语法、编译器、函数与字段注册表、语法高亮
src/lib/engine/    滑动窗口状态、表达式求值、规则引擎、回放、团伙分析
src/lib/data/      列式 schema、确定性演示数据生成器、CSV 导入、种子规则
src/lib/workers/   分析 Worker 与消息协议
src/lib/state/     应用状态（规则包、版本、数据集）、Worker 客户端
src/lib/pages/     规则 / 回放 / 团伙 / 名单 / 版本 五个页面
tests/             DSL、引擎、生成器单元测试
```

## 已知边界

- 规则与版本保存在 `localStorage`，清空浏览器数据会丢失（可在「版本历史」逐版查看）。
- 上传数据没有标签，回放只展示命中与决策分布，不计算命中率/误杀。
- 关联分析是规则之外的独立视图，命中不会自动写回回放结果。
